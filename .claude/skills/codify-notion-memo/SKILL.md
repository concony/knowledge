# codify-memo — Notion メモを Vault ノートに昇華する

Notion の生メモは「そのとき思ったこと」の断片で、多くは一般論のように見える。このスキルの目的は、メモを整形して保存することではなく、**メモが書かれた状況を復元し、対話を通じて「その人の経験に根ざした再利用可能な知見の核」を取り出して**、この Vault のノートにすることである。

单なる転記は価値が低い。この Vault は [[一般知識だけのノートは作らない]] [[一般知識よりも個人経験由来の知識を優先する]] という方針を持つ。メモが一般的な主張に見えるときこそ、「なぜ今この人がそれを強く思ったのか」という復元困難な核を掘り当てることが、このスキルの中心的な仕事になる。

## 全体の流れ

1. 対象メモを特定する
2. メモの文脈を復元する（Task → 親タスク → Purpose を辿る）
3. Vault の運用方針を読み直す
4. 関連する既存ノートを探索する
5. 対話で「復元困難な個人の核」を抽出する
6. ノートの種別と構成を判断し、ユーザーに確認する
7. ノートを作成し、相互リンクを張る
8. コミットする
9. Notion の `Codify` を `Done` に更新する

急いで書き始めない。3〜6 が本体で、ここを飛ばして転記すると価値の低いノートになる。

## 1. 対象メモを特定する

「DB_メモ一覧」データベースから、まだ Codify していないメモを取得する。

- Database ID: `2f8fda24-8479-4261-b1e8-8f1a2b515fa8`
- Data source: `collection://0a5f52cc-2bb6-4c17-b4eb-c4d21c1a66a0`

直近の未 Codify メモを新しい順に取る SQL（`notion-query-data-sources`）:

```sql
SELECT "名前", createdTime, "Codify", "userDefined:URL", url
FROM "collection://0a5f52cc-2bb6-4c17-b4eb-c4d21c1a66a0"
WHERE "Codify" IS NULL OR "Codify" != 'Done'
ORDER BY datetime(createdTime) DESC
LIMIT 5
```

ユーザーが特定のメモを指しているならそれを対象にする。一覧から選ぶ場合は、上記を表示して「どれから深掘るか」を確認する。原則として **1 回に 1 メモ**を丁寧に扱う。

### DB_メモ一覧のスキーマ（要点）

- `名前`（title）: メモ本文の要約または全文
- `Codify`（status）: `Not started` / `In progress` / `Done` / `Archived` … 昇華の進捗
- `Task`（relation → `collection://0e033a87-042d-47cf-a6fd-457a5ee1750b` = DB_タスク一覧）: メモが書かれたタスク
- 本文は `名前` とは別に、ページ本体（content）に入っていることがある。`notion-fetch` でページを開いて本文を確認する
- `Parent-note` / `Sub-note` / `Ref-note`: メモ間の関連

## 2. メモの文脈を復元する

メモ単体では状況がわからない。`notion-fetch` でメモページを開き、本文と `Task` リレーションを取得したら、**タスクの親子を上流に辿る**。

```
メモ (DB_メモ一覧)
  └ Task            → 何をしていたときのメモか
      └ Parent item → その作業が属する上位タスク（GitHub issue など）
          └ Purpose → プロジェクト（例: BTI.project.xxx）
```

各段を `notion-fetch` で開き、「どのプロジェクトの、どのタスクの、どの局面で書かれたメモか」を立体化する。これが後の「ケース」の骨格になり、ユーザーの記憶を呼び戻す手がかりになる。

## 3. Vault の運用方針を読み直す

ノートを書く前に、必ず現在の運用方針を確認する。作業ごとに方針が更新されている可能性がある。

- `AGENTS.md` — 記録時の標準ワークフローとノート記述の原則
- `20_Views/View - ノート管理.md` — 運用方針の入口
- 必読: `10_Notes/ノートの種類と記述ガイドライン.md`、`10_Notes/残すべきかどうかの判断基準.md`、`10_Notes/一般知識だけのノートは作らない.md`、`10_Notes/タグ運用方針.md`

## 4. 関連する既存ノートを探索する

メモの主題に関わるキーワードで既存ノートを検索し、似た知見・重複・追記先・対立や補完する見方を確認する。

```bash
grep -rl -e "キーワード1" -e "キーワード2" 10_Notes 00_Inbox
```

ここで判断したいこと:

- **すでに同じ知見があるか** → あれば追記・再構成の対象。新規で重複を作らない
- **既存の「型」に乗るか** → 例: 自分の傾向を扱うテーマは「法則（付き合い方）＋ケース（破綻した経験）」のペアで書かれている（完璧主義のノート群が典型）。同種の話は同じ型に合わせると体系が揃う
- **リンクを張る相手** → 上位の見方や関連ケース

## 5. 対話で「復元困難な個人の核」を抽出する

ここがこのスキルの心臓部。メモの文言をそのまま一般論として書くのではなく、ユーザーに状況を思い出してもらいながら、次を掘る。

- **何が具体的に起きたのか**（固有名・数字・時系列）。メモの抽象的な主張の裏にある実際の出来事
- **そのとき何を考え、何をした / しなかったのか**
- **なぜそう思うに至ったのか**。その人の傾向・環境・過去の誤解など、後から復元しにくい部分
- **次に同じ状況ならどうするか**

一般論に見えるメモほど、「なぜ今それを強く思ったのか」を問う。実体験が出てこないメモは、[[残すべきかどうかの判断基準]] に照らして「記録しない」判断もありうる。

複数のメモが同じ問題意識のクラスタを成していることに気づいたら、それをユーザーに伝え、まとめて 1 つの法則＋代表ケースにするかを相談する。

## 6. ノートの種別と構成を判断し、確認する

`10_Notes/ノートの種類と記述ガイドライン.md` の 4 種別から選ぶ。

- **法則・見方** `#type/principle` — 再利用可能な考え方・判断基準
- **ケース・エピソード** `#type/case` — 具体的な経験・失敗・違和感
- **ルール** `#type/rule` — ある条件で必ず適用する行動
- **View** `#type/view` — 知識への入口・地図

経験由来のメモは **ケース＋そこから抽象化した法則のペア**になることが多い（[[抽象知識はケースとセットで残す]]）。

書き始める前に、**タイトル案・種別・各ノートの骨子・既存ノートとの差分**をユーザーに提示して合意を取る。ここで構成を固めてから書く。

## 7. ノートを作成し、相互リンクを張る

- 配置は `10_Notes/`（refined なノート）。まだ生の断片なら `00_Inbox/` もありうる（`10_Notes/フォルダ構成と役割分担.md` に従う）
- タグは `10_Notes/タグ運用方針.md` の許可セット（`type/*` と `topic/*`）のみ
- 文体・抽象度・見出し構成は既存ノートに合わせる。「事前情報のない今の読者」が自然に読めるように書く
- ケース ↔ 法則、および関連する上位ノートへ **双方向にリンク**する（片方向で終わらせない）
- 追記主義に流れない。既存ノートが今の体系に照らして不整合なら、削除・統合・再構成してよい（`AGENTS.md` の「全体の完成度を最優先する」）

## 8. コミットする

作成・変更したノートをコミットする。ユーザーがコミットを望むか一度確認する。メッセージ例:

```
note: <テーマ>に関するケースと法則を追加
```

Vault 側のノートを先に確定させてから、次のステップで Notion の状態を更新する。こうすると「Codify 済み（= Done）なのに Vault にノートがない」という食い違いが起きない。

## 9. Notion の Codify を Done に更新する

コミットまで終わったメモは、`notion-update-page` で `Codify` を `Done` にする。これで一覧から消え、二重処理を防ぐ。

```
notion-update-page(page_id=<メモのID>, command="update_properties", properties={"Codify": "Done"})
```

## このスキルを使うときの心構え

- **転記ではなく発掘**。メモは入口にすぎない。価値は対話で掘り出す核にある
- **一般知識を量産しない**。検索や AI ですぐ出る内容だけのノートは作らない
- **1 メモずつ丁寧に**。まとめて機械処理せず、ユーザーの記憶と対話を通す
- **体系全体の完成度を見る**。1 枚のノートだけでなく、リンク先を含めた見通しがよくなるかで判断する
