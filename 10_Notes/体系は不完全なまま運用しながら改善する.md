# 体系は不完全なまま運用しながら改善する

体系化では、ある時点で完璧な体系を作ることよりも、不完全でも有用な体系を運用し、経験やケースから改善し続けることが重要である。

これは [[小さく試して高速に改善する]] という見方を、知識体系・分類体系・哲学体系に適用したものである。

## 完璧な体系を待つと運用が始まらない

体系化は、対象が複雑であるほど完璧に作り切ることが難しい。欲求、人生設計、知識管理のようなテーマでは、要素同士が重なり合い、時間とともに自分の理解も変わる。

そのため、最初から完全な分類や矛盾のない体系を作ろうとすると、考え続けるだけで運用が始まらない。運用されない体系は、経験によって検証されず、改善の材料も得られない。

## 有用な体系とケースの往復で改善する

体系は、最低限有用な段階で使い始める。

```mermaid
flowchart LR
    useful[有用な体系] --> cases[経験・ケース]
    cases --> improve[体系の改善]
    improve --> operate[さらに運用]
    operate --> cases
```

この循環を回すことで、体系は現実の経験に合わせて更新される。最初の体系が不完全であることは問題ではない。むしろ、不完全な体系を運用するからこそ、どこが不自然か、何が足りないか、どの分類が使いにくいかが見えてくる。

重要なのは、体系を固定された完成版として扱わないことである。体系は、判断や行動を助けるための暫定的な道具であり、経験によって改善される前提で運用する。

## 欲求分類への適用

欲求分類も、最初から人間の欲求を完全に網羅するためのものではない。今の自分が上位目的に立ち返り、タスクや関心の優先順位を見直すために、最低限有用な軸として使う。

実際に使う中で、分類しにくい欲求、重複している軸、判断に効かない項目が見つかれば、その経験をもとに体系を改善する。欲求分類の価値は、完成度の高さだけではなく、運用と改善のサイクルを回せることにある。
